# 반합리화 규칙 (Anti-Rationalization)

> Claude Forge Golden Principle #7(Ralph Loop) + #5(수술적 변경) + #11(반합리화) — KiiPS 적응
> Ralph Loop 감지 상세 로직 → [ralph-loop-detection.md](./ralph-loop-detection.md)

## 금지 표현 → 올바른 행동

| 합리화 | 올바른 행동 |
|--------|------------|
| "여기 온 김에 정리하자" | 요청된 것만 수정. 정리는 별도 요청 |
| "확장성을 위해 추상화" | 지금 필요한 것만. 반복 3회 이상 시 추상화 |
| "더 나은 방법 발견했으니 변경" | 사용자 승인 후 변경 |
| "이 패턴 전체에 적용하자" | 요청 범위만 수정 |
| "나중에 문제될 수 있으니 미리" | 현재 문제만 해결 |
| "이미 잘 동작하니 추가 검증 불필요" | 증거 없는 주장은 거짓 |
| "테스트 작성은 나중에" | 나중에 작성한 테스트는 happy path만 커버 |
| "간단한 수정이라 빌드 불필요" | 간단한 수정이 빌드를 깨뜨림 |

## HARD-GATE 규칙

### 다중 파일 변경 게이트
- **3개 이상 파일 변경 예정** → 사용자에게 변경 파일 목록 제시 후 승인 요청
- 승인 없이 진행 금지 (`multiFileGate.js` 자동 강제)

### 고위험 파일 게이트
다음 파일 변경 시 **반드시** 사용자 승인:
- `KiiPS-COMMON/`, `KiiPS-UTILS/` — 모든 도메인 모듈에 파급
- `pom.xml` (모든 모듈)
- `app-*.properties` (환경 설정 — 별도 deny rule도 존재)
- MyBatis mapper XML (SQL 변경)

## 수술적 변경 원칙

1. **추적 가능성** — 모든 변경 줄은 사용자 요청에 추적 가능해야 함
2. **"Bonus fix" 금지** — 발견한 다른 문제는 보고만, 수정은 별도 요청 시
3. **범위 고정** — 작업 시작 시 합의된 범위를 초과하지 않음
4. **관심사 분리** — 버그 수정 + 리팩토링 + 기능 추가를 한 작업에 혼합 금지

## KiiPS 특화 규칙

| 상황 | 금지 행동 | 올바른 행동 |
|------|----------|------------|
| JSP 수정 중 다른 JSP 오류 발견 | 함께 수정 | 보고만, 별도 작업 |
| SCSS 수정 중 구조 개선 필요 발견 | 리팩토링 병행 | 요청된 스타일만 |
| MyBatis `${}` 발견 | 전체 파일 `#{}` 변환 | 요청 범위 내 변환 + 나머지 보고 |
| Controller 수정 중 Service 개선점 발견 | 함께 수정 | Controller만 수정 + 보고 |
| 빌드 실패 시 의존성 정리 | 캐시 삭제 + 버전 변경 | 에러 메시지 분석 우선 |

## Ralph Loop 감지 (요약)

3가지 트리거 — 동일 파일 3회 편집(행위 가이드, 자동 훅 아님) / 연속 빌드 3회 실패(자동) / 에러 시그니처 3회 변경(자동) 시 HALT.
**상세 5단계 롤백 프로토콜 → [ralph-loop-detection.md](./ralph-loop-detection.md)**

## 핵심

```
요청된 것만 수정하세요.
발견한 것은 보고하세요.
승인 없이 확장하지 마세요.
```
